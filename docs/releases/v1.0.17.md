# Crux2 v1.0.17

The PlayStation 2 emulator PCSX2 as a native homebrew title for a jailbroken PS5 (`PPSA99249`), with a Big Picture interface made for the television and the DualSense.

> [!IMPORTANT]
> **Piracy is not condoned.** This release contains no games, no BIOS files, no console firmware and no decryption keys, and none will ever be provided or linked to. Use only **legally obtained backups of games you own**, made yourself from your own discs, and a BIOS dumped from **a PlayStation 2 you own**. Please don't ask for, or post links to, games, BIOS files, firmware or keys in issues or discussions: they will be removed.

> [!NOTE]
> **An unofficial port.** This is not a build of the PCSX2 project and is not supported by it. Please don't report its problems to PCSX2.

## What's new in v1.0.17

v1.0.16 was not published: its changes are part of this release.

Added:
- **Variable refresh (VRR)** (Settings > Interface > PlayStation 5, off; experimental): at 120 Hz on a TV with VRR, each frame is shown as soon as it is ready.
- **Graphics driver on a core of its own** (Settings > Emulation, on): the graphics driver's thread no longer shares the GS thread's core, so the GS thread has the core to itself.

Changed:
- **Less work on the GS thread**, the thread that limits the heaviest scenes: besides the driver's thread moving off its core, the auto-flush test is worked out once per strip in every vertex format that carries only vertex data (it was once per vertex outside PCSX2's two built-in formats), and a texture upload skips mipmapped textures it does not touch instead of checking each of their levels.
- **Built on the newest Mesa main** (27.0.0-devel of 2026-10-31): fixes to the shader compiler and to how graphics pipelines are hashed for the shader cache.
- **Built on PCSX2 v2.9.150** (was v2.9.142): game database fixes, vibration shown in the inputs display, and more.
- **GS dumps record 1 second by default** (*GS dump length*: 1, 2 or 5 seconds), are compressed on worker threads so recording slows the game less, and the "dump saved" message gives the file's size.
- **The boot log names each vertex format a game draws in** (lines starting `GS: PS5: packed format`).
- **The content version is `01.017.000`.**

Fixed:
- **120 Hz fell back to 60 Hz on TVs with VRR**: before the first frame such a TV refreshes at 48 Hz, which was taken for a TV still at 60 Hz. The boot log now says which rate was chosen and why.
- **The README's list of what does not work** still named features Crux2 has.

## Also new since v1.0.0

Added:
- **The version, WIP, the build number and "by Press5elect"** in the top bar, under the clock (v1.0.15).
- **USB controllers (experimental)**: DualShock 3 / SIXAXIS with pressure-sensitive buttons, Xbox 360 pads, guitars, drums and other USB pads.
- **Console language** (Settings > BIOS, and per game), and **Start the PlayStation 2 menu**.
- **Statistics on the on-screen display**: draws, barriers, render passes, copies and read-backs a frame, and the graphics chip's time by kind of pass.
- **Record a GS dump** in the quick menu (saved to `snaps/`), with either renderer.
- **Slow moments in the boot log**: a `slow:` line whenever a game stays under full speed for 2 seconds, saying where the time went.
- **paraLLEl-GS**: its own figures on the on-screen display, Automatic quality steps its samples, Dithering works with it, and its pictures can be shared with the graphics device (experimental, off).
- **Render targets without compression** and **Keep read render targets uncompressed** (both experimental, off; Graphics > Advanced).

Changed:
- **Every setting's description is rewritten** in short, plain English; settings PCSX2 also has use PCSX2's own description (v1.0.15).
- **Frames queue while a game is behind**: in heavy scenes the emulation no longer waits at every frame for the graphics thread. A lit scene I test with went from 81% to 95-100% speed (*Queue frames while the game is behind*, on).
- **Far less work at light sources**: draws through the rasterizer ordered view keep their render pass (about 4,000 passes a frame down to about 40), fewer barriers and fewer copies of the picture.
- **Built on PCSX2 v2.9.142** (was v2.9.138) and **Mesa 27.0-devel's RADV** (was 26.2.0): cheaper draws, fewer cache flushes, fixes to compressed depth and colour buffers.
- **paraLLEl-GS** compiles its shaders in the background and keeps them between sessions, takes the display settings, and works with Hardware download mode.
- **Renderer is one choice**: Hardware (Vulkan), Software, paraLLEl-GS.
- **The on-screen display is one panel** in sections, with 1% and 0.1% lows and a frame-time graph.

Fixed:
- **A game could freeze a few seconds after it started** (v1.0.15): a lost wake-up between the emulation and graphics threads when the frame queue changed.
- **The graphics chip's own hardware bugs** are worked around as for its real generation (shader compiler hazards, two geometry hang guards).
- **The driver's shader cache** could switch itself off on the console.
- **Graphics settings that take effect at the next start** now do so at each game's start, not only when Crux2 starts.
- **paraLLEl-GS**: pictures of dots or a frozen frame, dithering of 32-bit frame buffers, fringes at polygon edges.
- **The D-pad's Up and Down** stopped working after stepping Renderer through Software.
- **Opening Settings stopped Crux2**; on-screen figures showed nothing when switched on.
- **Games played one after another slowed down**: the previous game's textures are freed when it closes.
- **The PS2's start-up ran at double speed at 120 Hz**.

## Tested for this release

On the PC, for this exact build: the host tests, the interface tests (every settings row changed every way, about 625,000 frames of random button presses with the sanitizers, a picture of every screen) and the release check pass.

On my PS5: this build ran the heaviest scenes I test with and worked well. VRR has not been tried on a TV that has it. The USB controllers have not been tried on a console.

## Known issues

- paraLLEl-GS is slower than PCSX2's renderer in the heaviest game I test with, and its picture is softer by design.
- The free BIOS is early work: many games reach their menus and go no further. Use a BIOS dumped from your own PlayStation 2.
- RetroAchievements' hardcore mode is not offered.

## Install or update

1. Copy the `PPSA99249` folder from the ZIP to your homebrew folder on the console (`/data/homebrew/`), over an older one if you have it.
2. Your settings, memory cards, states and games stay: with a folder `/data/crux2`, Crux2 keeps them there, outside the title folder.
3. Your own games in `games/` (or on a USB drive or a share), your own BIOS in `bios/`. None included, none ever will be.
4. Read `LEGAL.txt` and `README.md` in the folder. Shaders are compiled again once after the update.

## Reporting problems

Open an issue with `crux2-boot.log` and `logs/emulog.txt` from the title folder (Settings > System can copy them to a USB drive), copied before Crux2 is started again. Never attach games, BIOS files, firmware or keys.
