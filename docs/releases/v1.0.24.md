# Crux2 v1.0.24

> [!IMPORTANT]
> No games, BIOS files, firmware or keys are included, and none ever will be. Use only legally obtained backups of games you own and a BIOS dumped from your own PlayStation 2.

The GS thread is split in two: one thread reads the game's graphics commands and another draws, so games that were held back by the GS thread hold their speed.

## Added
- **GS Thread Split** (Settings > Picture > Graphics, ADVANCED; on, two threads, by default): the thread that reads the game's graphics commands and decides when a draw is complete hands every draw, upload, palette load, memory move and frame end, in order, to a second thread that draws them on a core of its own. The picture is drawn by the same code, in the same order, with the same state. **Check (One Thread)** does the same work on one thread, to compare the picture; **Off** is the single thread as before. The split is not used (the boot log says why) with the software or GPU-target CLUT fixes, hardware AA1, a game's own memory-move fix, GS dumping, or paraLLEl-GS.

## Changed
- The profile the title is compiled with is trained again, with the GS thread split on.
- With the split on, the overlay's GS figure is the thread that reads the graphics commands; the boot log's `gs split:` lines say how busy the drawing thread is.

## Fixed
- **The graphics switches under Graphics > Advanced** (Uncompressed Feedback Targets, Disable Render Target Compression, Leave out barriers with nothing to wait for, Reuse copies of the picture) were read only when the title started, for most games: a game's own choice, or a change made since the start, was not used. They are read again at each game's start.

## Tested
On a PS5: test builds of this code with the split on two threads were played. A game held back by the GS thread ran at 100% on average at 4x over five minutes, under 95% for 3 s in all and a 1% low of 59.7 fps, where v1.0.23 ran it at 99% with 12 s under 95% and a 1% low of 51-54 fps; a second game held back by the GS thread ran at 99% at 4x. Six games were played with the split on while training the profile. The release candidate itself is being played as these notes are written. Not checked on a console with the split on: loading and saving states, resets, and settings changes in the middle of a game. On a PC: the host tests, the interface's walk-through of every screen, the check that no setting was lost, and the release check of the ZIP.

## Installation
- Copy the `PPSA99249` folder to `/data/homebrew/` on the console, over an older one if you have it.
- Your games, BIOS files, memory cards, save states and settings are kept.
- Read `LEGAL.txt` and `README.md` in the folder.

## Reporting problems
- Open an issue and attach `crux2-boot.log` from the title folder (written after a crash, a hang or Save the log). Don't attach games, BIOS files, firmware or keys.
- If a game's picture is wrong or it hangs, try it with **GS Thread Split** set to Off for that game, and say whether that changed it.
